# RQ1 最终结果：检测边界偏移对 RCA 的影响

## 执行范围

实验运行 RE1 的 375 个案例、9 个边界偏移和两个公开基线（BARO、CIRCA），共
6,750 次调用。6,721 次成功并进入指标汇总；29 次为上游基线异常（OB: BARO 18、
CIRCA 9；SS: BARO 2）。失败集中于三个数据/窗口异常案例：OB 的
`currencyservice_loss_1`（两个基线均在全部 9 个偏移失败）、OB 的
`productcatalogservice_cpu_3`（BARO 在全部 9 个偏移失败），以及 SS 的两个
BARO +300 秒失败。失败不计入均值，应在后续选择性方法中作为不可诊断/拒判事件处理。

## 结论

RQ1 得到支持，但影响程度取决于基线与系统。BARO 在小偏移（-60 至 +60 秒）内较稳定，
而 +300 秒使全局 AC@1 从 0.689 降至 0.164、MRR 从 0.792 降至 0.293；三个系统均出现
退化，TT 最严重。CIRCA 在 OB 与 SS 上也在极端偏移下明显退化：OB 的 AC@1 从 0.452
降至 0.105，SS 从 0.312 降至 0.160。TT 的 CIRCA 在 oracle 边界已接近性能下限，因此
该系统不宜作为其“相对退化”的强证据。

结果证明将检测时刻视为精确输入会带来可量化风险，也为后续的候选边界后验、跨窗口
聚合与选择性拒判提供实验动机。可复现汇总由
`scripts/summarize_rq1.py --input artifacts/rq1_full.json --output artifacts/rq1_summary.json`
生成。
